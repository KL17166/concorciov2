# Admin · Users (rotas de compatibilidade)

> **Escopo:** este arquivo documenta **somente** `src/routes/admin/userRoutes.ts` (4× `router.post`, linhas 8–11). A regra real de Pessoas mora em `src/routes/admin/peopleRoutes.ts` → documentada em `docs/admin/people.md`. Os 4 POSTs abaixo **delegam** para `src/controllers/admin/peopleController.ts`. Montagem: `src/routes/admin/index.ts:80` (`router.use(userRoutes)`, paths já absolutos `/users/...` → prefixo final `/admin`).
> **Gate global POST:** `src/routes/admin/index.ts:35-43` — todo POST passa por `csrfMiddleware.validateToken` (forms legados enviam `_csrf` hidden). `isAdmin` (`src/middlewares/adminAuthMiddleware.ts`): sessão `MASTER`/`MANAGER`/`SUPPORT`, senão `302 /admin/login` + flash `error` (`Por favor, faça login como administrador.`). `requireCapability` negado → flash `error_msg` (`Seu perfil não pode executar a ação "people.X".`) + `302 Referer || /admin/dashboard` (função `deny`).
> **Matriz relevante** (`src/security/adminCapabilities.ts:31-54`): `MASTER` tem as 4 capabilities; `MANAGER` tem `people.create` + `people.edit_profile` mas **não** `people.change_password`/`people.delete`; `SUPPORT` não tem nenhuma das 4 (todos os POSTs negados). `CLIENT` nunca passa `isAdmin`.
> **Telas:** `src/views/pages/users/{index,form}.ejs` são **legadas** (nenhum GET `/users*` existe mais em `userRoutes.ts`; os GETs antigos vivem como redirect em `peopleRoutes.ts:9-15`). Tela corrente: `src/views/pages/people/*`.

### `POST /admin/users/new`
- **Gate:** `isAdmin` + `people.create` (`userRoutes.ts:8`)
- **Ativado por (tela):** legado `src/views/pages/users/form.ejs:35` — `<form action="/admin/users/<%= editing ? editUser.id + '/edit' : 'new' %>" method="POST">` (modo criação), botão submit do form. Tela corrente equivalente posta em `/admin/people/new` (`src/views/pages/people/form.ejs:21`, botão `Criar cadastro`); este endpoint existe para forms antigos/integrações.
- **Request:** body → `peopleController.createPerson` (`peopleController.ts:96-136`): `name` (string, obrigatório, trim), `email` (string, obrigatório, trim+lowercase), `cpf` (string, obrigatório — só dígitos após `replace(/\D/g,'')`, exatos 11), `phone` (string, opcional → `null`), `password` (string, obrigatório, `length >= 8`), `role` (string, opcional), `address_cep|street|number|complement|neighborhood|city|state` (strings, opcionais → `serializeAddress`, `peopleController.ts:18-29`; retorna `null` se sem `street/city/cep`). Form legado envia ainda `role` (select CLIENT/MANAGER/SUPPORT/MASTER, `users/form.ejs:64-69`) + partials `person-fields` (`name,email,cpf,phone`) e `address-fields`.
- **Resposta do servidor:** nunca `render`. Sucesso → `redirect /admin/people` + flash `success_msg` = `Pessoa/conta criada com sucesso.` (`peopleController.ts:129-130`). Falhas → `redirect` (abaixo).
- **Efeitos:** **trava de papel** (`peopleController.ts:101`): `role = (actorRole==='MASTER' && ALL_VALID_ROLES.includes(requested)) ? requested : 'CLIENT'` — não-MASTER sempre cria `CLIENT` mesmo enviando outro `role`. Escrita: `prisma.user.create` (`peopleController.ts:117-127`, `passwordHash = hashPassword(password)`). Sem e-mail/alerta. CSRF validado antes do controller.
- **Erros:** validação (`peopleController.ts:103-106`) → `302 /admin/people/new` + `error_msg` `Nome, e-mail, CPF válido e senha com pelo menos 8 caracteres são obrigatórios.`; duplicado e-mail/CPF (`peopleController.ts:108-115`) → `302 /admin/people/new` + `E-mail ou CPF já cadastrado.`; exceção → `302 /admin/people/new` + `Erro ao criar pessoa/conta.`; sem capability → `deny` (ver escopo).

### `POST /admin/users/:id/edit`
- **Gate:** `isAdmin` + `people.edit_profile` (`userRoutes.ts:9`)
- **Ativado por (tela):** legado `src/views/pages/users/form.ejs:35` (modo edição, action `/admin/users/<id>/edit`). Tela corrente equivalente: `src/views/pages/people/form.ejs:48` — `<form method="post" action="/admin/people/<%= person.id %>/profile">`, botão `Salvar perfil` (aponta para path `/people/.../profile`, **mesmo handler** `updateProfile`).
- **Request:** params `id` (string, obrigatório). Body → `updateProfile` (`peopleController.ts:194-236`): `name` (string, trim; sem validação de vazio), `email` (string, **obrigatório**, trim+lowercase), `phone` (string, opcional → `null`), `address_*` (opcionais, mesmo `serializeAddress`). CPF **não** é editável por aqui (não lido do body).
- **Resposta do servidor:** nunca `render`. Sucesso → `302 /admin/people/:id/edit` + `success_msg` `Perfil atualizado com sucesso.` (`peopleController.ts:229-230`).
- **Efeitos:** **trava de e-mail** (`peopleController.ts:209-212`): se actor não é `MASTER`/`MANAGER` e `email !== atual` → bloqueia (`canChangeEmail` só true p/ MASTER/MANAGER em `editPersonForm`, `peopleController.ts:178-186`; input fica `readonly` na tela, `people/form.ejs:52`). Escrita: `prisma.user.update` (`peopleController.ts:220-228`). Sem alerta/e-mail.
- **Erros:** inexistente → `302 /admin/people` + `Pessoa/conta não encontrada.`; `email` vazio → `302 /admin/people/:id/edit` + `O e-mail é obrigatório.`; troca de e-mail por perfil sem poder → mesma rota + `Seu perfil não pode alterar o e-mail.`; e-mail em uso (`peopleController.ts:214-218`) → mesma rota + `Este e-mail já está em uso.`; exceção → mesma rota + `Erro ao atualizar o perfil.`; sem capability → `deny`.

### `POST /admin/users/:id/delete`
- **Gate:** `isAdmin` + `people.delete` (`userRoutes.ts:10`) — na prática só `MASTER` (matriz `adminCapabilities.ts:32-40`).
- **Ativado por (tela):** legado `src/views/pages/users/index.ejs:238` — modal `#deleteModal`, `<form id="deleteForm" action="" method="POST">` com action preenchida via JS `confirmDelete(id)` → `/admin/users/<id>/delete`, botão `Sim, Excluir Usuário`. Tela corrente equivalente: `src/views/pages/people/details.ejs:113` — `Zona de risco`, form `POST /admin/people/<id>/delete`, botão `Excluir cadastro` (path diferente, mesmo handler `deletePerson`).
- **Request:** params `id` (string, obrigatório). Sem body útil (só `_csrf`).
- **Resposta do servidor:** nunca `render`. Sucesso → `302 /admin/people` + `success_msg` `Pessoa/conta excluída com sucesso.` (`peopleController.ts:329-330`).
- **Efeitos:** **trava anti auto-exclusão** (`peopleController.ts:323-326`): `id === actorId` → bloqueia. Ordem de escrita (`peopleController.ts:327-328`): `prisma.auditLog.updateMany({userId:id} → {userId:null})` e depois `prisma.user.delete`. Sem e-mail/alerta.
- **Erros:** auto-exclusão → `302 /admin/people` + `Você não pode excluir a própria conta.`; exceção (ex.: FK — usuário com subscriptions/contratos) → `302 /admin/people` + `Não foi possível excluir esta pessoa/conta.`; sem capability → `deny`.

### `POST /admin/users/:id/reset-password`
- **Gate:** `isAdmin` + `people.change_password` (`userRoutes.ts:11`) — na prática só `MASTER`.
- **Ativado por (tela):** legado `src/views/pages/users/index.ejs:266` — modal `#resetPasswordModal`, `<form id="resetPasswordForm" action="" method="POST">`, action via JS → `/admin/users/<id>/reset-password`, botão `Resetar Senha Agora` (texto do modal: senha aleatória exibida na tela seguinte). Telas correntes equivalentes: `src/views/pages/people/details.ejs:49` botão `Gerar Senha Aleatória` e `src/views/pages/people/form.ejs:93` botão `Gerar Senha Aleatória Automática` (ambas postam em `/admin/people/<id>/reset-password`, mesmo handler).
- **Request:** params `id` (string, obrigatório). Sem body útil (só `_csrf`). Ignora qualquer senha enviada — sempre gera.
- **Resposta do servidor:** nunca `render`. Sucesso → `302 /admin/people/:id` (details, **não** edit) + flash `success_msg` = `` `Senha temporária de ${person.name}: ${temporaryPassword}` `` (`peopleController.ts:310-311`) — **a senha em claro transita na flash** (visível uma vez na tela seguinte).
- **Efeitos:** `crypto.randomBytes(12).toString('base64url').slice(0,12)` (`peopleController.ts:308`) → `prisma.user.update({passwordHash: hashPassword(tmp)})` (`peopleController.ts:309`). Sem e-mail/alerta. (Difere de `changePasswordDirectly` — `/people/:id/password`, mínimo 6 chars — que **não** tem rota `/users/*` correspondente.)
- **Erros:** inexistente → `302 /admin/people` + `Pessoa/conta não encontrada.`; exceção → `302 /admin/people/:id` + `Erro ao alterar a senha.`; sem capability → `deny`.

> **Conferência de cobertura:** `userRoutes.ts` tem 4× `router.post` (linhas 8, 9, 10, 11) — todos documentados acima, 4/4. Nenhum `router.get/put/patch/delete` no arquivo. `canManageRole` (`adminCapabilities.ts:65-68`, uso em `peopleController.ts:250`) vale para `POST /people/:id/access`, que **não** tem espelho `/users/*` — por isso não há seção de troca de papel aqui (ver `people.md`).
